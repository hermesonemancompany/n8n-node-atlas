01 · Architecture

Think in boundaries, not boxes.

A reliable workflow separates ingress, normalization, decisioning, side effects, and operations. The visual language below uses n8n-editor-style node cards, connectors, labels, and a grid canvas rather than generic architecture rectangles.

Ingress

Triggers establish contracts

Document event shape, authentication, replay behavior, response timing, and the correlation ID before adding business logic.

Execution

Items are the unit of work

Normalize types at boundaries, preserve stable identifiers, and avoid hidden dependencies on item position or branch ordering.

Operations

Side effects need safeguards

Use credentials, timeouts, bounded retries, idempotency keys, and an explicit error workflow around every fallible integration.

02 · Data model

Make data contracts explicit.

Expressions first

{ $json.customer.email } { $json.items.map(item => item.sku) } { $now.toISO() } { $('Normalize').item.json.customerId }

Use expressions for local mapping. Choose Code only for genuine multi-item aggregation, libraries, or stateful logic.

Boundary checklist

  • Required fields and types are explicit.
  • Null, empty, and missing are distinct.
  • Dates have an agreed timezone.
  • Remote failures are classified.
  • Binary size and retention are bounded.
  • External IDs are retained for replay.
03 · Reliability & security

Design for retries and failure.

Production gate: validate credentials, error paths, retry policy, rate-limit behavior, duplicate delivery, and partial failure before publishing a workflow.

Idempotency

Derive a deterministic key from provider event ID and operation. Check it before a write, then persist the result with the key.

Dead letters

Capture execution ID, node, correlation ID, sanitized input summary, and retry classification. Never put secrets in alerts.

Security boundaries

Keep tokens in n8n credentials, minimize PII, validate signatures before parsing, and treat all remote data as untrusted.

Observability

Carry correlation IDs and record outcome, duration, provider status, item counts, and the workflow version.

04 · Patterns

Reusable workflow recipes.

Paginated ingestion

Follow a provider cursor, cap pages, upsert by natural key, and persist the cursor only after a successful page.

Human approval

Persist pending state, authenticate the callback, validate current state, and make approve/reject idempotent.

Stateless sub-workflow

Define inputs and outputs as a versioned contract. Extract for reuse, isolation, testing, or an agent tool—not just canvas tidiness.
